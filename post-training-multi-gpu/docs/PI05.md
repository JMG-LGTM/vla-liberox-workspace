# Pinned pi0.5 integration and platform export

This repository contains a small independent adapter. It does not import the
platform repository, alter its environment, or vendor its UI. OpenPI is installed
as a separately pinned dependency, not copied into the Git repository.

The framework is tested with CPU fake models. The real
3.6-billion-parameter policy has **not been loaded or trained in this repository**.
Real weight conversion, model loading, GPU training and end-to-end inference
remain unverified. Real-policy single-GPU loss alignment, full BC50 training and
policy evaluation are required to validate model behavior. Model weights are
downloaded separately.

## Immutable sources and dependencies

- OpenPI: [`215abfb217dbac7d5f1273282331b9b1866c0479`](https://github.com/Physical-Intelligence/openpi/tree/215abfb217dbac7d5f1273282331b9b1866c0479).
- Base weights: [`Adam-YAN/pi05-liberox-base`](https://huggingface.co/Adam-YAN/pi05-liberox-base/tree/4664e4725d2e72c3a8af8b09adfda41eaf74514c),
  revision `4664e4725d2e72c3a8af8b09adfda41eaf74514c`.
- Python 3.11, Torch `2.7.1+cu128`, torchvision `0.22.1+cu128`,
  Transformers `4.53.2` plus the exact replacements supplied by pinned OpenPI.
- The installer uses OpenPI's `uv.lock` for its dependency tree, including the
  pinned LeRobot source dependency. An NVIDIA driver supporting CUDA 12.8 is
  required for the official cu128 wheels. No local CUDA toolkit is required.

The adapter, conversion installer and manifest contract were derived from
`vla_rynn_iql/pi05.py`, `pi05_assets.py`, `training.py:_publish_overlay`,
`model_artifacts.py` and the two setup scripts at platform `origin/server` commit
`e27f426`. The adapter follows the platform's vertical-only image contract and
schema-5 policy manifest. The actual OpenPI
model implementation remains upstream under its own license.

## Installation and obtaining weights

Use a new environment; setup refuses other environment names to avoid patching
an unrelated Transformers installation. Commands do not ask interactive questions.

```bash
python3.11 -m venv "$HOME/envs/post-training-pi05"
source "$HOME/envs/post-training-pi05/bin/activate"
python -m pip install --upgrade pip setuptools wheel uv
python scripts/setup_pi05.py
export OPENPI_DATA_HOME="$PWD/cache/openpi"
python scripts/download_weights.py --output models/pi05_liberox_jax \
  --convert --converted-output models/pi05_liberox_torch --prefetch-tokenizer
```

The original download is pinned and records all original asset hashes in
`source_snapshot.json`. Conversion is forced onto CPU, can require substantial
host RAM and scratch disk, and never overwrites an existing output. It creates
`model.safetensors`, `assets/meituan/LIBERO-X/norm_stats.json`, and
`pi05_identity.json`. The identity binds both files, upstream commit, source
revision, conversion precision and native model geometry. Dry-run hashes those
files without importing OpenPI or creating the model. Hashes detect corruption;
only use converted repositories that you trust.

To use a converted private repository after its owner has separately uploaded it:

```bash
python scripts/download_weights.py --converted-repo OWNER/CONVERTED_MODEL \
  --revision FULL_40_CHARACTER_COMMIT --output models/pi05_liberox_torch
```

Both commands use the local Hugging Face credential store or `HF_TOKEN` and
support `HF_ENDPOINT` / `--endpoint`. Interrupted downloads resume through
`huggingface_hub.snapshot_download`; rerun the same command. No upload is performed.
See the [official download guide](https://huggingface.co/docs/huggingface_hub/guides/download).

## Offline server installation

On an internet-connected machine with the same Python ABI, Linux architecture and
compatible glibc, complete setup and tokenizer prefetch above. Transfer:

1. This repository and `third_party/openpi`, including `.git`, submodules and
   its workspace packages. Runtime verification requires the pinned Git checkout.
2. The populated uv cache (`uv cache dir`) and `wheelhouse/`; preserve uv cache
   symlinks and source checkouts. Install `uv`, `pip`, `setuptools`, and `wheel`
   from separately downloaded bootstrap wheels in the new environment.
3. Converted weights and the complete `OPENPI_DATA_HOME` cache, including
   `big_vision/paligemma_tokenizer.model`.
4. Dataset packages and their checksums.

Set `UV_CACHE_DIR` and `OPENPI_DATA_HOME` to the transferred directories, then run
`python scripts/setup_pi05.py --offline --wheel-dir /path/to/wheelhouse` in the
new dedicated environment. The installer runs `uv sync --offline --frozen` and
`pip install --no-index`. It fails if an artifact is absent instead of silently
selecting another version. Source Git dependencies are supplied by the uv cache;
a wheelhouse alone is insufficient. Set `HF_HUB_OFFLINE=1` during training.
The offline installation procedure has not yet been validated end to end.

## Training and preprocessing contract

Both frozen and full modes use the same flow-matching loss, averaged over each
sample's valid replay timesteps and seven real motor coordinates. The native
output is `[10,32]`; replay supervision is `[8,7]`. Padded times and coordinates
do not contribute to loss. BC averages sample losses; IQL applies detached
advantage weights in the runner.

`frozen` disables gradient computation in
`paligemma_with_expert.paligemma` and keeps that submodule in evaluation mode
even after repeated `train()` calls. It trains approximately 0.69B parameters;
`full` trains approximately 3.6B. Both enable upstream gradient checkpointing.
Real parameter counts are logged after model loading; these approximate counts
come from the reference platform and have not been remeasured here.

Replay caches supply uint8 HWC images already flipped vertically, with
`image_flip_vertical=true` and `image_flip_horizontal=false`. The adapter does
not flip them again. Raw proprioception and actions stay on CPU until OpenPI's
data transforms run; DDP must not automatically move the complete batch to CUDA.
OpenPI quantile normalization uses `(x-q01)/(q99-q01+1e-6)*2-1` without clipping.
There is no VLA gripper remapping. By default both IQL and standalone critic fit
their **critic** quantiles on training roots only; the actor always receives raw
actions/state and applies its own immutable base statistics. This deliberate
choice allows critic checkpoints to move directly into IQL. It differs from
the reference platform's default of using base statistics for both components.
The exact critic statistics travel in its export. An explicit normalization JSON
can also be supplied; base statistics can be extracted with `load_normalization`
without loading the actor or importing OpenPI.

## Platform-compatible export

The final run export contains native upstream parameter names in `actor.pt`, the
unaltered base identity in `pi05_identity.json`, and the exact schema-5
`policy.yaml` field set. The compatibility hash uses the platform's original
canonical JSON algorithm. Additional training metadata lives in
`export_provenance.json`, outside the strict policy manifest.

For transfer to the evaluation machine, export **before** copying and set that
machine's exact base directory. This generates the corresponding parent snapshot,
model settings and hashes together; do not manually modify `policy.yaml`.

```bash
python scripts/export_policy.py \
  --checkpoint outputs/bc50/checkpoints/update_00000800.pt \
  --output exports/pi05-bc50-reproduce \
  --platform-base-checkpoint /ABSOLUTE/EVALUATION/PATH/models/pi05_liberox_torch
```

The destination folder name must equal `policy_id`. Transfer the complete
`pi05-bc50-reproduce/` directory into the evaluation platform's configured policy
registry, preserving that name. Select the new overlay through its normal policy
selection flow. The platform must have exactly the base checkpoint described by
the identity; the small actor package does not replace base weights. No script
here writes the running platform registry, changes its `latest` symlink, restarts
the platform, or edits any platform policy YAML.

`training_step` records completed actor optimizer updates in this repository;
IQL's critic-only warmup is subtracted. The sidecar explicitly records the unit.
The platform field name stays unchanged. The checkpoint and its adjacent SHA-256
JSON sidecar are required for manual export.
Critic-only runs produce standalone critic checkpoints and cannot export actor
packages. Export tests validate native parameter scope, exact fields, hash
integrity, both BC/IQL manifest variants, path rebasing and the checkpoint export
CLI using a CPU fake model. Loading a trained real actor into the platform
remains unverified.

Full-backbone configurations now use rank-local optimizer checkpoints. Their
public `.pt` path is a symlink into a complete immutable model generation;
`export_policy.py` resolves it and checks its model SHA without loading optimizer
shards. Copy the full checkpoint directory, including hidden generations, if
training restoration is needed. Platform policy packages remain ordinary
self-contained directories with the unchanged schema-5 field set.
