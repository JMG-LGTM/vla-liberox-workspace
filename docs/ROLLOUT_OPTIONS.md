# 成功判定与成功后停止

## 成功判定：单步 done 即成功

系统规则在 `vla-adapter-rynn-iql/configs/runtime.yaml` 的 `data.success_consecutive_steps`，现在是 `1`：完整任务的原生 `done` 出现一次就确认成功。仿真记录的成功确认、批量评测、新建训练数据集和奖励都读这个值；服务器评测 `configs/server_evaluation.yaml` 的 `success_streak` 也设为 `1`，保持一致。

- 已冻结的评测配置如果写的是 `success_streak: 5`（旧规则），仍然可以读取和续跑，按冻结时的值执行。
- 已建好的训练数据集保存了创建时的值，不会因为改系统规则而改变。
- 改这个值后需要重启平台（进程内只读一次）。

## 成功后 2 秒自动停止（`stop_after_success`）

在“创建仿真”的草稿里勾选，开始运行后锁定，默认关闭。旧客户端不传字段、旧记录缺少字段时都按关闭处理。

| API 字段 | 类型 / 默认值 | 行为 |
|---|---|---|
| `stop_after_success` | 严格布尔值 / `false` | 第一次收到原生成功信号后，再执行 2 秒仿真时间，然后正常结束并保存轨迹。 |

- 计时按控制步数，不按墙上时间：20 Hz 时，在第一次成功那一步之后再执行 40 个动作。之后成功信号变回假也不会重新计时。
- 手动停止和总步数上限仍然优先，不会为了凑满 2 秒超过总步数。
- 策略、SpaceMouse 和 FACTR 控制都支持。正常结束走原来的保存流程，保留成功后的短尾段。
- 二次推理和人工续跑继承源记录的设置；从历史前缀继续时，前缀里的成功不会启动新分支的倒计时。
- 字段经过创建草稿、更新草稿、开始会话和保存记录（`run.json`、`config.yaml`、轨迹元数据）传递。
